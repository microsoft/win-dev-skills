## Retained infrastructure failures and correction

The first saved four-row schedule, experiment
`94ea2cd8-cfe5-42a9-9ae1-945ce92980e7`, used an unqualified custom-agent name.
Its first T invocation exited 1 before model work; F/L/B stayed `not_run`.
The CLI requires `winui:winui-dev`. That entire schedule is retained in
[the plumbing export](2026-09-24-cli-plumbing.json). Missing usage remains
unknown, not zero.

The first independent T assessment exposed an evaluator error:
WinApp 0.6.1 rejects `--quiet` with `--json`. Known-good scaffold calibration
then exposed a PowerShell PID type-predicate precedence bug and WinApp's
hash-identical `AppX` staging path. These were corrected without editing any
agent output. A separately versioned evaluator assessed **all four** immutable
deliverables uniformly. Original failed assessments and calibration artifacts
remain retained locally; they are infrastructure failures, not evidence that T
failed to launch.

The original UWP app was independently built and exercised: all three pages,
four deferred rectangles, navigation reset, adaptive mail/panes/accounts and
both photographs were observed. A later pure-evidence calibration found that
the photo matcher assumed a centered crop, while the source renders the top-left
crop. Correcting only the crop origin made both actual source photographs pass
the unchanged error threshold of 24 (errors 12.8867 and 12.56); asymmetric
goldens and blank/wrong-photo mutants were added. This does not change the four
constrained outcomes, which all stopped at the earlier navigation gate.

The [sanitized constrained export](2026-09-24-constrained.json) contains every
scheduled row, native exits, times, authoritative credit/token aggregates,
stage assertions, resolved package versions/content hashes, treatment and
scaffold file hashes, and hashes of retained raw evidence. Raw sessions, local
configuration and absolute user paths are not published.

Observed model-call/tool-call counts were B 13/44, T 23/67, L 16/66 and F 61/130.
The CLI emitted no `assistant.usage` per-call component events in these runs;
this is missing granularity, not missing aggregate billing. Credits come only
from top-level `totalNanoAiu / 1e9`. Model/agent aggregate views are not added
again. Uncached input and cache-read input remain separate. Peak context
occupancy is unavailable; cumulative replay tokens are not a substitute.

The worker was a supervised local Windows desktop, **not** an isolated VM.
Fresh workspaces and `COPILOT_HOME` did not isolate OS authentication, machine
policies, NuGet/build caches or other filesystem access. Two missing signed
UWP framework dependencies were installed during source preflight, before the
first actual model migration; that change is recorded in the frozen preflight.

## Separate owned-runtime follow-up

A second four-arm lane was prospectively authorized rather than repeating the
confounded build-only protocol. All arms may exercise only their own app,
serially, under the same model, source, candidate and budgets. It has a separate
saved schedule and is not pooled with the constrained cohort.

Admission required exact-package collision checks, target-contained image
paths, actual creation intervals, approved binary hashes and retained process
handles. A real known-good packaged-app preflight confirmed that the guard
stopped the owned broker-launched process, removed only its exact registration,
preserved source bytes and left an unrelated process alive. Ambiguous cleanup
blocks continuation; there is no prompt-only safety fallback.
